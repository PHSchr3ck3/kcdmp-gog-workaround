Date: 2026-10-30. Repository with the workaround, scripts and derivation:
https://github.com/PHSchr3ck3/kcdmp-gog-workaround

Summary: the build gate can be passed locally with a hand-derived builds.json entry, but
247 of the 548 anchors cannot be recovered without the original byte patterns. Hence this
request.

2. What the client logs (client.log, 0.48.1)
   build gate: unknown game build (timestamp 1782121515, pdb 4B3F7D2D4D22434DA6CA550A88ED0D8C)
   self-test: the table of supported game builds inside the DLL holds 3 build(s)

3. What was established here
   - The launcher compares Timestamp + SizeOfImage (--check-game: PDB and SHA-256 are
     ignored). An entry with the values above is accepted as "supported".
   - The client reads builds.json next to KcdMp_client.dll. A custom entry with 277
     anchors (73 rtti, 197 slot/pattern_slot/string_slot, 2 export, 4 runtime,
     1 ctor_data/gEnv) passes the gate and the engine boots (gEnv 0x4917800, confirmed
     by the client as "matches the gEnv anchor"; 21 hooks; server connection and the
     server's login UI work).
   - Still missing: 247 pattern anchors (the byte patterns are not stored in the client)
     plus 23 slot anchors and 1 rtti anchor. Those features stay off.

4. Request
   - Please generate a "gog" entry for exactly this WHGame.dll with
     tools/sigscan/sigscan.py (all 548 anchors) and add it to builds.json, or
   - publish tools/sigscan/sigscan.py together with the pattern data so the entry can be
     reproduced here.
   An entry with only the 277 derivable anchors is not full support.

5. Attachments / evidence
   tools/gog_anchors.json lists all 277 derived anchors with method and vtable/slot;
   docs/TECHNICAL.de.md (German) documents the derivation and the 23/247 open anchors.
   The full builds.json can be provided on request. No game or mod binaries are
   redistributed; the entry was derived from a legally owned GOG copy.
